# Spec-Driven Development

Use a concise product spec before implementation. Clarify the target user, primary workflow, non-goals, constraints, data model, API contracts, UX states, and acceptance checks. Treat ambiguity as a design risk and resolve it before generating code prompts.

Verification:
- Requirements map to user-visible outcomes.
- Non-goals prevent scope creep.
- Acceptance checks are testable.
